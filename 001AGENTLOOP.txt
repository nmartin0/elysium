2.1 Correctness at the boundary -- what the model is trusted with
-------------------------------------------------------------------------------
-

LB-1  ARITHMETIC IN PROSE, UNVERIFIED. The synthesis step computes
      figures in text. TWO FIXES, not one: (1a) compute the figures in
      CODE first and give the model the results, (1b) add a NUMBER
      CHECK that fails closed, the way the citation check already
      does. Do not do 1a without 1b.

LB-3  SILENT PARTIAL ANSWERS. Three failures the code DETECTS are
      presented to the user as complete answers. Pairs with AL-6: one
      stop reason instead of four booleans, and partial answers marked
      as partial.

LB-2  THE AGENT CAN ONLY FILTER BY EQUALITY, although
      `core/filters.py` implements range, in, not_in, date_range,
      contains and relative dates -- and the schema shown to the model
      HIDES EVERY FIELD'S DATA TYPE, so it could not choose a typed
      operator even if it knew one existed. Also no ordering and no
      limit. This is F-18 on the roadmap, where it is recorded as a
      FEATURE whose priority is the owner's: propose before building.

LB-4  OUTPUT SHAPE NOT ENFORCED AT DECODING. `format: json` only.
      Pairs with AR-5 (constrain the step choice fully, leave
      synthesis free).

LB-10 INJECTION DEFENCE IS A PROMPT INSTRUCTION. Pairs with AL-2.

2.4 Speed, and the VM
-------------------------------------------------------------------------------
-

Probe P31 measured that **97.5% of each hop's prompt is an exact
prefix of the previous one**, and only 16% of what is sent needs
reading.

AR-1  VERIFY PREFIX-CACHE REUSE. Potentially several-fold, no code
      change. Do this first: it costs a measurement.
AR-2  MOVE PER-HOP NOTES OUT OF THE SYSTEM PROMPT. They sit at its
      END today, which invalidates the cache for everything after
      them. Append-only context instead.
AR-4  READABLE TOOL RESULTS: names beside ids.
AR-5  CONSTRAIN THE STEP CHOICE FULLY; keep synthesis free.
AR-3  PERSIST EACH USER'S SYSTEM-PROMPT KV (needs llama-server: an
      owner decision, D2).
AR-6  GEPA prompt optimisation. Needs AL-6 first.
AR-7  PLAN CACHING feeding router growth.
AR-8  N-GRAM SPECULATIVE DECODING (llama-server).
AR-9  HETEROGENEOUS MODELS with policy-gated escalation. OWNER
      DECISION D3: this sends data off the VM.
AR-10 FINE-TUNE ON OUR OWN TRACES. OWNER DECISION D6.

MODEL_SELECTION-001 says the ~10 minutes per hop is mostly READING THE
PROMPT (~5.4 tokens/s prefill, ~1.5 decode -- 10-25x below published
figures for this model class). CHECK THE VM's AVX2/FMA FLAGS FIRST; if
they are missing, fix the CPU model before comparing anything. Then
phi4-mini -> Qwen3-4B-Instruct-2507 is an owner decision (D1) worth
~4.5x less time per SUCCESSFUL answer over four steps, after the
bench.

`scripts/llm_bench.py` exists in the audit set as a patch and is NOT
applied. It is read-only and standalone; applying it is a good early
move if you want real numbers.
