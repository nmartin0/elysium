# Elysium decisions

One entry per decision, ADR-lite: id, date, decision, reason, consequences.
The roadmap (`docs/roadmap.md`) cites these ids and never restates them. A
decision changes only by a new entry that names the one it supersedes; the old
entry stays, marked **Superseded by**. History of how each was reached is in
git and in `docs/archive/planning-history.md`.

Status words: **Decided** (owner said yes), **Decided by direction** (follows
from the owner's 3 November 2026 direction, applied by default; the owner can
veto it under Q-N22 in the roadmap), **Superseded**.

Groups: **B** = earlier binding decisions (before the 3 November plan); **D** =
the refactor plan's decision list (owner, 3 November 2026); **N1-N21** = the
production roadmap's decisions (owner, 3 November 2026); **N22 onward** = the
finalisation of the roadmap (3 November 2026); **N46 onward** = the design
settlement; **N66 onward** = the parallel-execution pass.

## How to add a decision

Append a row with the next free id. One decision per row. Write the reason as
evidence (a measurement, a source, an invariant), not as preference. Name what
it costs to reverse. A new primitive, registry or resource kind needs an entry
here before its code merges (design rule DR6 in the roadmap).
