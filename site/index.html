Ask your data questions.
Without handing it over.

Elysium answers questions — and, with permission, makes changes — against your organisation's data through a declared ontology. The model never gets direct database access, and is never trusted to judge what it is allowed to see.

Try the demo How it works

An ontology, not a connection string

Object types, fields and links are declared once in YAML and resolved live against your real databases at the moment they are needed. Nothing is copied into a vector store, and nothing is answered from a snapshot the model happens to remember.

Declared, not inferred

A field the ontology does not declare does not exist, as far as any question is concerned.

Resolved live

Answers come from your databases at the moment the question is asked, through adapters that are structurally unable to write.

Writes are proposals

A change the model suggests is a proposal a person approves. The approver's own permissions are re-checked at the moment they approve.

The model is never the thing deciding

Every read is checked against the asking user's grants before it is served, and mandatory access control runs underneath that: an object in a compartment you cannot see is indistinguishable from an object that does not exist.

Per field, per row

Permissions are granted per object type and per field. Two colleagues asking the same question can correctly get different answers.

One organisation per instance

A server instance runs one organisation's data. There is no multi-tenant store to get wrong.

Everything is logged

Every field access, every refusal and every approved write, with the request that caused it.

See it working

The demo is a real Elysium instance with synthetic data. Ask it questions, propose a change, approve it as somebody else, and watch the audit log fill in.
