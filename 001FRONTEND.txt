2. HOW TO RUN THINGS
================================================================================

    cd ui
    npm ci
    npm run lint        # oxlint --deny-warnings, tsc --noEmit,
                        # prettier --check, knip  (ALL FOUR must pass)
    npm test            # vitest
    npm run e2e         # playwright (needs `npm run e2e:install` once)
    npm run dev         # vite, against a running back end

The back end runs separately:

    python -m scripts.run_sync          # populate the mirror
    uvicorn api.app:app                 # serve

READ `AGENTS.md` AND `PRINCIPLES.md` BEFORE WRITING ANYTHING. They are
short and they are the house style: AGENTS.md is the how, PRINCIPLES.md
the why. `RULES.md` carries hard rules learned from mistakes -- read it
too. The commit-message and verification conventions in AGENTS.md apply
to your work exactly as they do to the back end's.

3.1 CSS -- two real defects
-------------------------------------------------------------------------------
-

CSS-S1-01  DEFECT. `.app-frame--sidebar-collapsed .app__sidebar` is
           defined TWICE, same layer, no media query. The FIRST
           definition (index.css ~:609) is entirely dead, and its
           comment describes an `aria-hidden` Shell.tsx behaviour that
           was deliberately removed. Delete it.
           WHY IT MATTERS BEYOND TIDINESS: the duplicate-selector test
           (S3-01 below) could not see it, which is the actual finding.

CSS-S1-02  DEFECT. The cascade-layer architecture is DECLARED and never
           used: six of seven layers are empty in the shipped build, so
           every rule we write is unlayered and the ordering the
           declaration promises does not exist.
           THE AUDIT IS EMPHATIC that migration must be ONE PASS OR NOT
           AT ALL -- a half-migrated cascade is worse than none, because
           some rules would obey the declared order and others would
           not. Decide deliberately: migrate fully, or delete the
           declaration and say why.
           NOTE: AUDIT-09's own follow-up says layers ARE in use now for
           some rules, so re-measure before acting. Do not trust this
           line over what the built CSS says.

5. JOINT WORK -- DEFERRED, DO NOT START
================================================================================

Each of these needs a server change AND a UI change. Starting one from
either side alone produces a half-feature and a merge conflict. They
are deferred deliberately; they will be scheduled once the two lists
are drained, or sooner if the owner decides.

    UI-LIVE            Server-sent events. Needs a streaming endpoint
                       (none exists), an events table, fan-out across
                       workers -- and then the UI to consume it. The
                       security decision is already made and must hold:
                       AN EVENT CARRIES NO DATA. It says what KIND of
                       thing changed; the client refetches through the
                       same authorised endpoints, so MAC and roles apply
                       unchanged and no second read path exists.
    CONFIG-WRITE       UI edits written back to YAML through ruamel
                       round-trip. Needs a validating write endpoint,
                       compare-and-set, an audit entry per write, and a
                       new generation at an epoch boundary.
    PIPELINE-BUILDER   A sub-app plus the endpoints behind it.
    ACCESS-1..6        A classification model in the ontology and policy
                       layer, plus the admin UI that edits it.
    ALERT-1            Freshness alerting: a server-side evaluation and
                       a UI surface.
    GOLD-3d provenance Per-object provenance from silver's lineage. The
                       rest of GOLD-3d is yours (§3.6); this part has no
                       endpoint.
    E-07               A link's id type depends on the read path (ints
                       live, strings mirrored). The FIX is back-end and
                       needs an owner decision; when it lands your types
                       may need updating. Do not work around it in the
                       UI meanwhile -- that would hide the defect.
    PA001-G12 (API)    The API emits decimals as floats, so
                       Decimal("12345678901234567.89") does not survive.
                       Back-end fix; may change what you receive.

IF YOU FIND MORE JOINT WORK, add it here rather than starting it.


================================================================================
6. HOW TO ASK FOR A BACK-END CHANGE
================================================================================

Append to a file called `FRONTEND_REQUESTS.md` on your branch, one
entry each:

    ## <short title>
    WHAT I NEED: the endpoint, field or shape.
    WHY: what the UI cannot do without it.
    WHAT I DID MEANWHILE: nothing / a temporary display / a skipped
        feature. Say which.

That file is yours; the back-end instance will read it and reply in
the same file. Do not edit any back-end file to unblock yourself, even
trivially -- two instances editing `api/routes.py` is exactly the
conflict this division exists to prevent.


================================================================================
7. STANDARD OF EVIDENCE
================================================================================

This repository holds work to a specific standard, and it applies to
the UI as much as the pipeline:

  - MEASURE, DO NOT ASSUME. "The cascade layers are unused" is a claim
    about the built CSS; check the build, not the source.
  - WRITE THE TEST THAT WOULD HAVE CAUGHT IT. CSS-S3-01 exists because
    a test could not see a duplicate selector. Fixing the selector
    without fixing the test leaves the next one to be found by an
    auditor.
  - RUN A CONTROL. After a fix, break it deliberately and confirm the
    test fails. A test that passes both ways is not a test.
  - SAY WHAT YOU DID NOT CHECK. An honest gap is worth more than an
    implied guarantee.
